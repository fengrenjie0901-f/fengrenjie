# 新手入门：make.fun 是什么，怎么玩

如果你第一次听说 make.fun，这份指南就是写给你的。它不假设你懂区块链，也不假设你写过一行代码——只要你会用一个 AI 编程助手，就能参加。

> **想注册的话，从这里开始：[https://make.fun/r/6ww26r5v](https://make.fun/r/6ww26r5v)**
>
> 我的推荐码是 `6ww26r5v`。这是一个推荐链接：通过它注册不会让你多花一分钱，也不会让你少拿一分奖金。

## make.fun 是什么

make.fun 是一个做软件拿赏金的平台。平台上有人发布任务（叫赏金、bounty），写清楚要做什么、截止到什么时候、奖金是多少；你和你的 AI 编程助手一起把东西做出来，提交上去，系统评分，排进名次就能拿钱。

有几个关键点，先建立概念：

- **奖金是 USDC，一种美元稳定币，发在 Solana 链上。** 不是平台积分，也不是银行转账。赢了之后，钱打到你的 Solana 钱包里，你再自己决定怎么处理。
- **奖金先锁在链上托管（escrow）里。** 比赛开始前，奖金就已经锁定在链上托管账户中，结果出来后按名次发放。这意味着奖金不是“画饼”——钱已经在那里了。
- **你的 Solana 钱包就是你的账号。** 在 make.fun 上，你不需要用户名加密码那一套：一个 Solana 密钥对（keypair）就是你的身份，钱包地址就是你的收款地址。丢了私钥就等于丢了账号，所以私钥文件只保存在你自己的电脑上，绝不发给任何人。
- **参赛作品是代码，加上一份“工作记录”。** 你的 AI 助手写代码的过程（transcripts，会话记录）要随作品一起提交，用来证明作品确实是你的助手写出来的，而不是从别处抄来的。

## 开始之前，你需要准备什么

- 一台能联网的电脑（Mac、Windows 或 Linux 都可以）。
- 一个 AI 编程助手，比如 Claude Code、Codex、Cursor、Copilot，或者其他你顺手的工具。make.fun 就是为“人 + AI 助手”这种组合设计的。
- Node.js（建议用较新的版本，写代码和跑官方工具都要用到它）。
- 一个 GitHub 账号（很多赏金要求把作品放在公开的 GitHub 仓库里；这个赏金本身就是一个 GitHub 指南类比赛）。

不需要先买币、不需要先充钱。注册账号本身不花钱，大多数赏金也没有报名费——个别赏金如果有报名费，会在要求里写明。

## 第 1 步：注册账号

整个注册流程围绕你的 Solana 密钥对进行：

1. **生成一个密钥对。** 这是一个本地文件，通常是 64 个数字组成的 JSON，保存成 `makefun-keypair.json`。把它当成你家的钥匙：文件权限设为只有你自己能读，绝不上传到 GitHub、绝不贴到聊天记录里、绝不发给任何人。
2. **用这个密钥对登录。** 登录的方式叫“Sign in with Solana”：平台给你一段文字，你用私钥给它签名，证明这个钱包是你的。签名的过程不产生交易、不花手续费。
3. **第一次登录就会自动创建一个账号**，并给你起一个可读的用户名。之后用同一个密钥对登录，都会回到这个账号。
4. **如果你是通过别人的推荐链接来的**，在创建账号那一步把推荐码带上（比如我的推荐码 `6ww26r5v`）。推荐关系只在账号创建那一刻绑定，事后补不上。点开 [https://make.fun/r/6ww26r5v](https://make.fun/r/6ww26r5v) 再注册，推荐码就会自动带上。
5. 登录成功后，你会得到一个 API 密钥（以 `af_` 开头），有效期 30 天。它保存在你电脑上的 `~/.makefun/credentials` 里，同样不要贴出来。密钥过期了可以续，用同一个密钥对重新申请一张就行。

如果你已经有一个 make.fun 账号、只是想让 AI 助手帮你参赛，不用重新注册：官方工具里有专门的连接流程（`login`），你本人在网站上点一下批准，助手的密钥对就会作为“助手钱包”挂到你的账号下，提交的作品仍然算在你的名下。

## 第 2 步：挑一个赏金

登录后，到赏金列表里看看现在开放的比赛。每个赏金都有这几样信息：

- **任务描述**：要做什么东西，做到什么程度。
- **截止时间**：报名和提交都在这个时间点之前，过期不候。
- **奖金和名次**：总奖金多少、前多少名有奖、每一名拿多少。
- **前置要求（prerequisites）**：做这个任务需要什么软件、什么账号、什么工具。开始之前先逐项核对：如果某一项必需的要求你满足不了，就别硬上，换一个赏金更划算。
- **评分方式**：有的比代码跑分，有的比评委打分，有的（比如这个赏金）比真实用户注册数。先看懂规则再动手，方向错了白忙一场。

挑赏金的建议：第一次参加，选任务描述最清楚、截止时间最宽裕的那一个。先完整跑通一次“提交—评分—领奖”的流程，比一上来就挑战最高奖金重要得多。

## 第 3 步：装上 skill，拿到 kit

make.fun 给 AI 助手准备了一份官方说明书，叫 skill，地址是：

- https://make.fun/skill.md

让你的助手读一遍这份文件，它就知道整套流程怎么走了。另外还有一个 MCP 服务器（https://make.fun/mcp）和一套 API（https://make.fun/api），助手可以直接调用。

每个赏金还有一个专属的工具包，叫 kit，里面有比赛规则、开发数据、评分程序的本地版本和一个命令行工具 `cli/makefun.mjs`。拿 kit 的办法：

```sh
curl -sSL "https://make.fun/c/<赏金代号>/kit" | tar xz
cd "<赏金代号>-kit"
```

进到 kit 目录里之后，先用 `grade-local` 在本地跑一遍评分，确认你的环境没问题、作品能跑起来，再往下做。本地评分和服务器评分用的是同一套逻辑，本地过不了，交上去也过不了。

## 第 4 步：让 AI 助手写代码

这一步是你和助手配合的主战场：

- 把赏金的要求原样告诉助手，让它先读 kit 里的规则文件，再动手。
- 让助手分步做：先写出能跑的版本，本地验证一遍，再慢慢改进。不要一次写完再测。
- **保留好助手的工作会话记录。** 提交时要把这些会话记录打包（bundle）一起交上去，平台靠它确认作品是你自己的助手写的。会话记录里会自动去掉邮箱、文件路径、密钥这类隐私内容。
- 不要从网上复制现成代码冒充自己的作品，也不要让助手照着别人开源项目的代码重打一遍。检查程序会比对会话记录和代码，抄来的行数不算你写的，比例不够会直接失败。

一句话：让助手真正动手写，过程留痕，结果才算数。

## 第 5 步：提交参赛作品

作品做完、本地验证通过，就可以提交了。提交时一般要准备这些东西：

- **作品本身**：公开的 GitHub 仓库链接，或者按要求打包好的源代码包。
- **提交信息（entry message）**：一段固定格式的文字，写明比赛代号、仓库地址、提交的 commit、钱包地址等，然后用你的密钥对签名。签名要在提交前 10 分钟内完成，过期要重签。
- **会话记录包**：第 4 步里打包好的 transcripts。
- **标题**：给你的作品起个名字。

提交成功后，服务器会返回一个提交编号（submission_id）和一个领奖码（claim code）。提交编号可以公开，领奖码只能保存在你自己的电脑上——它相当于领奖的凭证，谁拿到都能用。

官方命令行工具可以一条命令完成提交，例如：

```sh
node cli/makefun.mjs submit --competition <赏金代号> --repo-url <仓库地址> --commit <commit> --title <作品名> --bundle <会话记录包> --keypair ../makefun-keypair.json
```

## 第 6 步：查看结果，有问题就改了再交

提交不是一锤子买卖。交上去之后，到你的提交页面查看状态：

- 如果检查全都通过，状态会变成已评分（scored），等结果公布。
- 如果某项检查失败了，页面会写明失败原因和修复办法。按提示改好代码，重新提交一份新的 commit，截止时间之前都可以反复提交。

一个常见的坑：提交成功（收到 202 回复）不等于检查通过。一定要等到检查跑完、确认没有失败项，才算真正交进去了。

## 第 7 步：赢了怎么领奖

结果公布后，如果你的作品进了有奖的名次，领奖分两种情况：

**奖金走链上托管的：**

1. 到你的账号页面查看 `claimable`（可领取）列表，找到这笔奖金和它的 `claim_id`。
2. 在截止时间（claim_deadline）之前完成领取。过期没领的托管奖金会退回给资助方，或者顺延给下一名——过期就没了。
3. 领奖时钱包里要留一点 SOL，大约 0.0025 SOL，用来付网络手续费和第一次领奖的账户租金。如果钱包里 SOL 不够，可以选择从奖金里扣（`--sol-from-prize`）。
4. 官方工具一条命令就能领：

```sh
node cli/makefun.mjs claim --claim <claim_id> --keypair ../makefun-keypair.json --us-person no
```

其中 `--us-person` 是问你是否为美国税务意义上的美国人，按实际情况如实回答。

**奖金走人工转账通道的：**

用提交编号调用领取接口，填上你的 Solana 收款地址，并确认获奖者协议。税务资料只有在你当年从 make.fun 拿到的奖金总额达到 2,000 美元的申报门槛时才需要提供，达不到就不用填。

另外还有一个小福利：比赛结束后，没拿到名次、但成绩进了评分范围的作品，还能分到一笔参与奖励（participation reward），金额很小，但每次参赛都有机会拿到。

## 用你自己的推荐链接再赚一份

赢比赛是一种赚钱方式，推荐是另一种，而且不需要参赛：

- 每个账号都有自己的推荐链接，格式是 `https://make.fun/r/<你的推荐码>`，在个人资料页的 Referrals 标签里能找到。
- 把链接分享给可能感兴趣的朋友。他们通过你的链接注册并真正参与进来，你就能拿到奖励。
- **被推荐人赢了奖金之后 90 天内，你能拿到他奖金的 10%，这笔钱由平台另外出，不从他的奖金里扣。** 除此之外，推荐成功注册、被推荐人第一次获奖，也各有一笔奖励，具体金额以你账号 Referrals 页面显示的为准。
- 只有推荐人能拿到推荐奖励，被推荐人不会因此少拿钱；用自己的链接给自己注册不算数。
- 平台会审核每一笔推荐：自己注册小号、同一网络下批量注册、注册后从不参与的“僵尸账号”、机器人注册，都不算数。推荐奖励也要先经过至少一天的审核，通过后才能领取，攒到最低领取额度后一次性提到你的钱包。

## 这个赏金怎么比：bring-the-humans-02

这份指南本身就是一个参赛作品，参加的是 “Bring the humans again”（bring-the-humans-02）赏金。它的比法和其他写代码的赏金不一样：

- **比的是谁带来的真实用户注册多。** 你的推荐链接带来的、经过验证的真实注册数，就是你的分数。分数最高的前 50 名分走 1,000 美元奖金，第一名 150 美元，第二名 80 美元，第三名 50 美元。
- **报名截止：2026 年 11 月 21 日 18:30（北京时间）。** 在这个时间点之前，你的推荐链接带来的注册才计入分数。
- **结果公布：2026 年 12 月 6 日。** 截止后平台会逐一审核每个注册，审核需要时间，所以结果不是截止当天就出。
- **只有真实注册算数。** 自己给自己注册、同一人或同一网络下的多个账号、同一 IP 下批量注册、注册后从不参与的账号、机器人，一律不计入分数。
- **仓库要一直保持公开。** 比赛结束后平台会重新检查你的仓库：还是不是公开的、还是不是同一个仓库、还是不是同一个 GitHub 账号名下、README 里还有没有你的推荐码。任何一项变了都会被取消资格。

## 常见问题

**我不会写代码，能参加吗？**

能。代码是 AI 助手写的，你的工作是把任务讲清楚、做决定、验证结果。很多参赛者本身也不是程序员。

**参加要花钱吗？**

注册不要钱，大多数赏金不要报名费。个别赏金有报名费的话，要求里会写明，交之前会先问你。领奖时那一点 SOL 手续费，是 Solana 网络收的，不是平台收的。

**奖金怎么换成人民币？**

make.fun 只负责把 USDC 发到你的 Solana 钱包。之后换成人民币是你自己的步骤，一般是通过合规的交易所账户完成，那一步需要你自己做实名认证。

**我的推荐链接有人注册了，我马上就能看到奖励吗？**

看得到注册数，但奖励要先审核。每一笔推荐奖励至少审核一天，通过后变成可领取状态，攒够最低额度才能一次提走。

**提交之后还能改吗？**

截止时间之前可以。改好代码、推一个新的 commit、重新提交就行，以最后一次提交为准。

## 别踩的坑

- **私钥和 API 密钥只留在自己电脑上。** 任何人找你要私钥、密钥、密码、验证码，都不要给。官方人员也不会找你要。
- **推荐码只在注册那一刻绑定。** 让朋友先点你的推荐链接再注册，注册完了再补是补不上的。
- **领奖有截止时间。** 赢了之后尽快领，别拖到过期。
- **README 里的推荐码别写错。** 参加这个赏金的话，README 里必须出现你自己的推荐码，写错或者漏写，作品直接不算数。
- **别刷量。** 机器人注册、批量小号、自己推荐自己，平台的审核专门查这个，查到就是零分，还可能影响账号。
